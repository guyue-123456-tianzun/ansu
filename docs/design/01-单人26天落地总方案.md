# 安宿 · 单人 26 天落地总方案

> 说明：本文是 **Demo-P0 保底档**（26 天、1 人）。全量版（不设硬截止、恢复 P1/P2、新增 RAG 学习）见 `05-全量版范围与RAG学习方案.md`。

> 适用前提：**1 人全栈、代码从零、11-12 开始、12-06 提交、竞赛 90 秒答辩优先、26 天固定**。
> 本方案不是把原文档“压缩执行”，而是重新定义一条**可交付的垂直切片**：保 90 秒主链路，砍掉不影响主链路的页面与角色。

## 三、架构落地修正（10 条）

> 这些是对原文档的“可执行化修正”，不是推翻。每条都说明原因与代价。

### 3.1 判定路径：同步判定 + 1 秒调度

- **演示注入**：`POST /api/demo/inject` 内同步调用 `SafetyEngine.evaluate()`，不等待 2 秒轮询。
- **真实摄入**：`@Scheduled(fixedDelay=1000)` 读取新 `load_record`，调用同一个 `SafetyEngine`。
- **原因**：原方案 2 秒 Java 轮询 + 3 秒学生轮询，最坏 5 秒，3 秒指标必挂。
- **代价**：注入接口耗时略增（毫秒级），可接受；真实摄入仍有 1 秒延迟，但演示路径可控。

### 3.2 学生端轮询：1 秒，不是 3 秒

- 学生首页/告警详情 1 秒轮询；页面隐藏时暂停。
- 大屏 2 秒；申诉工作台 10 秒；通知 3 秒。
- **原因**：3 秒识别 + 3 秒轮询 = 最坏 6 秒；1 秒才能守住“3 秒可见”。
- **代价**：本地请求量增加，20 寝演示无压力；不做 WebSocket/SSE，避免复杂度。

### 3.3 Python 保持“薄 sidecar”

- P0 五个端点（按原文）：`/ai/explain`、`/ai/qa`、`/ai/briefing`、`/ai/simulate`、`/ai/health`。
- `/ai/qa` 可以“薄”：Java 规则优先，未命中再调 Python；Python 失败回规则。
- Python 只写 `load_record`；不碰业务表；不判申诉。
- **原因**：保留“Java 管事实、Python 管表达”的答辩叙事，又不让 Python 成为关键路径。
- **代价**：多一个进程；用模板/熔断兜底，Python 挂不影响主链路。

### 3.4 单 Vue 工程，双路由

- 一个 Vite 工程：`/login`、`/admin/*`、`/m/*`；构建产物复制到 Java `static/`。
- 管理端用 Element Plus；学生 H5 用 Vant 4（或手写移动 CSS，二选一，建议 Vant 省时）。
- 图表 ECharts 5；状态 Pinia；请求 axios。
- **原因**：两个工程会多出构建、部署、登录跳转、样式四套成本；单人扛不住。
- **代价**：首屏包体略大，按路由分包即可。

### 3.5 16 张表 + YAML/JSON，不扩表

- 白名单、时间带、阈值、信用规则以 `thresholds.yaml` 为唯一来源；`threshold_version` 存 `yaml_text/checksum/active`。
- 课程与题库放 classpath JSON；`learning_record.answers_json` 存作答，`certificate_id` 存证书。
- `notification` 自带 outbox 字段（status/retry/next_retry）。
- `demo_run.id` 16 位字符串；`dorm.id` 直接用房间号（314）。
- **原因**：扩表要重跑迁移、种子、Mapper、测试；单人时间不够。
- **代价**：YAML 不能直接 SQL 查询；启动时加载 + 内存缓存；API 返回解析后的 JSON。

### 3.6 鉴权：演示身份切换 + JWT，不做 SSO

- `POST /api/auth/demo`：按角色/宿舍换 JWT；HS256；12 小时；claims：`sub/role/dorm_id/display_name/jti`。
- 学生端所有查询强制 `dorm_id = token.dorm_id`；管理端复核要求 `manager/admin`。
- **原因**：原文 P0 不建复杂账号；演示最稳；SSO 依赖学校，不可控。
- **代价**：不是生产级账号体系；答辩主动说明“P1 接 CAS/企业微信”。

### 3.7 演示重置：run 作用域 + 脚本兜底

- `POST /api/demo/switch`：归档旧 run，清理 run 作用域数据，生成新 run。
- `POST /api/demo/reset`：管理员 + demo profile + 二次确认；清理业务表、重置寝室状态/信用、保留用户/阈值/主数据。
- `scripts/reset-demo.sh` + `python -m scripts.seed_demo --reset --yes`：双兜底，现场不依赖 UI。
- **原因**：切场景串数据是演示事故第一名。
- **代价**：重置逻辑要测 3 遍；必须备份种子。

### 3.8 时间与时区

- 库内 UTC；接口 ISO 8601 +08:00；业务时间带按 `Asia/Shanghai`。
- 时间带左闭右开：`[06:00,19:00)` 日间；`[19:00,23:00)` 洗漱；`[23:00,06:00)` 夜间。
- **原因**：夜间规则错 8 小时，整场演示会变成“白天分闸”。
- **代价**：所有时间转换集中在一个 `TimeBands` 工具类，禁止散落。

### 3.9 不引入 Redis / MQ / 微服务

- 单机 MySQL + 本地缓存（Caffeine 可选）+ `@Scheduled`。
- 单实例假设；定时任务不加分布式锁；用唯一键保证幂等。
- **原因**：26 天、1 人；引入中间件只会增加故障面。
- **代价**：不能水平扩展；答辩说明“试点单机足够，扩展时再加”。

### 3.10 离线优先

- ECharts、字体、图标本地打包；不引 CDN。
- 前端构建产物进 Java `static/`；演示不依赖外网。
- LLM 不可用时全模板；Python 不可用时 Java 模板。
- **原因**：答辩现场网络不可控。
- **代价**：构建体积增大；提前打包，现场不 npm install。

## 九、资源与环境

### 9.1 硬件

- 开发机：16 GB 内存以上，SSD；能同时跑 MySQL + Java + Python + Vite。
- 演示机：同一台或备用笔记本；提前装好 JDK/Node/Python/MySQL，或带 Docker 镜像。
- 第二台手机：学生 H5 扫码/输入地址；准备手机支架。
- 投影/转接头、电源、插排、离线热点（可选）。

### 9.2 软件与账号

- JDK 17+（推荐 21）、Maven、Node 20、Python 3.11、Docker Desktop（或本地 MySQL 8）。
- IDE：IntelliJ IDEA + VS Code。
- LLM：GLM API Key（或兼容 OpenAI 协议的国内模型）；无 Key 也能跑模板。
- Git 仓库：本地 + 远程私有仓库；每日提交。
- 录屏：OBS/系统录屏；2 段，各 2–5 分钟。

### 9.3 数据与素材

- 20 间宿舍：1F 101–105、2F 201–205、3F 311–315（含 314）、4F 401–405。
- 基线：UCI 分钟级（就绪）或合成 7 天 × 1 分钟/条 × 20 寝；足够画曲线；合成必须标 `source=seed`。
- 设备签名：热得快 800W/PF 0.99、吹风机 1800W/**PF 0.80**、饮水机 2000W/PF 0.98、PFC 电脑 1200W/PF 0.97、基线 32W。
- 课程：3 门 × 5 题；视频用 1 页图文/60 秒动画占位。
- 离线：ECharts、字体、图标、Vant/Element Plus 样式全部本地。

## 十三、可行性结论（必须让干系人知道）

1. **按本方案（Demo-P0）**：1 人 25 个开发日，8–10 小时/天，严格砍范围，交付概率中等偏高；前提是 D4/D10 冻结、每天过日目标、P1 全砍。
2. **按原文全量 P0**：原文自己按 **1.5 人** 设计；1 人 26 天不可行，至少 1.5–2 人或延长到 6–8 周。
3. **最大的不确定性不是写代码，而是“调稳定 + 对数字 + 练答辩”**；所以本方案把最后 6 天全部留给联调、彩排、交付，不再加功能。
4. **如果只能保一件事**：保 90 秒主链路（A 申诉版保底）；学习、问答、凭证、报修都可以延后。
