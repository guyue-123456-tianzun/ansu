## 五、对排期的影响

1. **UCI 基线**：如果 D2 前拿不到数据/清洗不成功，立即切合成基线，不占用 D3–D4；否则会拖垮 G0。
2. **演示身份切换**：比用户名/密码登录简单，T006 从 3h 降到 2h；省下的 1h 给 UCI 校验。
3. **原文 28 端点**：比我此前版本多 `safety/evaluate`、`student/alerts`、`repairs`、`manager/tickets`；其中 `manager/tickets`/`provenance` P1，`repairs` 可只做接口。净增约 2–3h。
4. **YAML 阈值**：比 JSON 配置少写 DDL，但要多写加载/校验/版本写入；净增约 1h。
5. **90 秒速通版**：如果选 B/C，需要多做“演示作答/预完成记录”开关；约 2–3h。建议放在 D18 演示控制里。
6. **总体**：更新后 WBS 约 **206–212h**，仍高于 25×8=200h；必须砍 P1 或把 UCI 降级为加分项。

## 六、仍然成立的裁决

以下判断不因原文而改变：

1. **1 人 26 天做全量 P0 不可行**；原文自己按 1.5 人设计。
2. **3 秒必须靠同步判定 + 1s 学生轮询**；3s 轮询与 3s 指标数学上冲突。
3. **90 秒不能假装播完 3 分钟微课**；必须速通或预完成，并明示。
4. **锁定中 urgent 漏电/温度必须告警**；原文代码是安全 bug。
5. **信用分账本只追加、申诉回滚不重算历史**；避免重复/负数。
6. **演示必须 run 作用域重置**；否则切场景串数据。
7. **P1 全部可砍，90 秒主链路不可砍**。
8. **模板/降级必须明示**，不把模板伪装成 LLM。
